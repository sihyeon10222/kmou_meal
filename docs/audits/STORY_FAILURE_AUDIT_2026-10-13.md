## 원인과 확인 한계

`StoryStorage.uploadImage`는 업로드를 한 번만 시도했다. 일시적인 서버/네트워크 오류도 곧바로 해당 Story 실패로 처리했다. 또한 SDK 오류의 `message`만 기록해 HTTP 상태와 Storage 오류 코드가 유실되었다. `<none>`만으로는 이번 요청의 정확한 서버 오류를 확정할 수 없다. 전후 요청 성공은 일시적 실패 가능성을 뒷받침하지만 증명하지는 않는다.

## 수정

- 이미지 업로드의 HTTP 408/429/5xx, 네트워크/타임아웃 및 응답 JSON 유실에 최대 3회 시도(1초, 2초 대기)를 적용한다. 그 외 오류는 즉시 실패한다.
- 재시도는 같은 실행의 객체 경로와 바이트를 사용하며 `upsert: false`를 유지한다.
- 응답 유실 뒤 중복 객체 응답이 오면 공개 URL의 JPEG 타입과 전체 바이트 일치를 검증한 경우에만 다음 단계로 진행한다. 기존 객체를 덮어쓰지 않는다.
- 공개 URL 조회는 별도로 최대 3회 시도한다. 이미 성공한 업로드나 Instagram 게시를 반복하지 않는다. 타입/바이트 불일치는 즉시 실패한다.
- 업로드 오류에 HTTP 상태, Storage 코드, 전송 오류 종류를 추가한다. 재시도 로그는 기존 비밀값 마스킹을 적용한다.
- 주간 피드 잠금 등 다른 Storage 쓰기에는 재시도를 추가하지 않는다.

회귀 테스트는 SDK를 통과하는 fetch 모의 응답으로 일시적/영구 오류, 재시도 상한, 응답 유실 후 중복 객체, 바이트 불일치 시 게시 차단, 공개 URL 실패, 잠금 쓰기 동작을 검증한다. 실제 Instagram 재게시는 이 수정 작업에 포함하지 않는다.
