# 2026-10-05 Story 실패 분석

## 확인된 원인

- 실행: [Daily KMOU Stories 37238001611](https://github.com/sihyeon10222/kmou_meal/actions/runs/37238001611), 대상 날짜 2026-10-05.
- 한국시간 06:57~06:58에 기숙사·승선생활관·학식의 게시와 활성 Story 확인이 성공했다.
- 교직원은 `today_teacher_full: 2026-10-05 teacher: 게시할 식단이 없습니다.`로 이미지 생성 이전에 실패했다. Instagram API 오류가 아니다.
- 분석 시 같은 날짜로 학교에 POST 조회한 응답은 `sch_date=2026/10/05`, 학식 양식 칸의 `*대체공휴일 미운영`, 교직원 표의 빈 `tbody`를 반환했다. 실행 당시 원본 HTML은 Artifact에 없어, 당시 응답과 완전히 같은지까지는 확인할 수 없다. 현재 응답과 실행 로그의 빈 식단 결과는 일치한다.
- `bf8c846`에서 추가된 실제 게시의 전체 빈 식단 거부 조건은 README의 빈 식단 안내 정책과 달랐다. 미리보기에는 이 조건을 적용하지 않아 미리보기 성공으로 실제 게시를 검증할 수도 없었다.

## 수정과 재발 방지

1. 정상 조회의 빈 식단은 네 식당 모두 안내 이미지로 게시한다. 주말 학식·교직원 skip 정책은 유지한다. 조회·파싱 오류는 게시하지 않는다.
2. 학식 파서는 표의 본문 누락, 열 수/colspan/rowspan 변경을 빈 메뉴로 숨기지 않고 실패한다. 정상 빈 tbody와 날짜 colspan 행은 허용한다. 응답에 `sch_date`가 있으면 요청 날짜와 대조한다.
3. 학식 조회 실패 Promise는 다음 교직원 조회에 재사용하지 않는다. 성공 응답만 같은 배치에서 공유한다.
4. 게시 성공 뒤 기록/활성 Story 확인 오류는 `published`와 media ID를 보존하고 경고로 기록한다. CLI 종료 코드는 1이지만 게시 실패로 표시하지 않는다.
5. Instagram GET만 제한적으로 재시도한다. 생성/게시 POST의 자동 재전송을 추가하지 않는다. 서버의 Retry-After도 준수한다.
6. Actions Summary와 실행 JSON에 정상 빈 메뉴, 실패 단계, 게시 ID, 후속 확인 경고를 남긴다.
7. 실제 10/5 표를 최소 fixture로 보존하고 빈 식단 실제 게시 경로, 손상된 표, 날짜 불일치, 조회 복구, 성공 후 확인 오류, GET/POST 재시도 범위를 회귀 테스트한다.

## 운영상 남는 한계

- Story의 새로운 호출은 의도적으로 새로운 게시다. 날짜/모드별 중복 방지나 잠금을 새로 도입하지 않았다. 전체 배치를 재실행하면 이미 성공한 식당도 재게시된다. 교직원만 복구하려면 `restaurant=teacher`, `meal=full`, `date=2026-10-05`로 실행한다.
- Instagram 게시 POST의 응답 유실은 성공 여부를 단정할 수 없다. 자동 재전송하지 않고 계정·container/영수증을 확인해야 한다. 외부 서비스 장애가 다시 발생하지 않는다는 보장은 할 수 없다.
- 정상 빈 교직원 식단을 휴무라고 추측해 표시하지 않는다. 학교가 안내한 문구만 그대로 쓰고, 나머지는 `등록된 식단 없음`으로 표시한다.
- 파서가 학교의 구조 변경을 감지하면 실패하므로 새 구조에 맞춘 수정이 필요하다. `sch_date`가 없는 HTML은 표만으로 날짜를 검증할 수 없다.
- 실제 게시/원격 반영은 별도 운영 단계다. 로컬 미리보기와 모의 게시 회귀 테스트로 확인하며 실제 Instagram 게시를 테스트 수단으로 사용하지 않는다.
