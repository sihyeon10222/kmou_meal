## 관찰과 선택

기존 4B 스토리에는 반찬 누락, 밥 중복, 지나치게 작은 식판, 거친 배경 경계가 보였습니다. 프롬프트는 배경과 식판 설명이 길고 실제 음식 이름과 위치가 떨어져 있었습니다.

## 코드 변경

- 기본 이미지 모델: `@cf/black-forest-labs/flux-2-klein-9b`. 품질이 낮은 4B로 자동 전환하지 않습니다.
- 한글 메뉴를 짧은 영어 시각 설명과 음식 종류로 변환합니다. 항목 수와 종류를 검증한 후 음식별 위치를 한 문장에 결합합니다.
- `밥/잡곡밥`, `밥/작곡밥`, `백미밥/흑미밥`은 이미지에서는 일반 밥 한 종류입니다. 스토리 메뉴 원문은 유지합니다.
- 밥은 일반식판 왼쪽 아래, 국그릇은 오른쪽 아래, 주찬·반찬·김치는 위쪽입니다. 원형식판의 큰 왼쪽 칸은 주메뉴에 사용합니다. 메뉴에 국·밥이 없으면 추가하지 않도록 명시합니다.
- 식판과 음식은 한 번에 생성합니다. 배경 경계는 바깥 방향으로만 부드럽게 처리하고, 빈 바깥 여백을 줄여 음식이 크게 보이게 합니다. 식판 안 음식을 잘라 붙이거나 따로 확대하지 않습니다.
- 승선생활관만 아침 이미지를 생성합니다. 학식은 제외합니다.
- 일일 한도 소진 오류는 즉시 재시도하지 않으며, 같은 준비 작업에서 아직 시작하지 않은 끼니 호출도 중단합니다.

`output/food-quality-comparison/2026-10-08-today_dormitory_full.jpg`는 비교용 영어 프롬프트로 생성한 9B 사진에 새 배경·여백 처리를 적용한 미리보기입니다. **새 자동 번역/분류 파이프라인의 통합 검증 결과가 아닙니다.**

## 초기화 후 남은 검증

```bash
npm run verify-food-images -- --live
```

이 명령은 실제 API를 사용하며 인스타그램에는 게시하지 않습니다. 기본 실행(`--live` 없음)은 API를 호출하지 않습니다. 생성 6건을 순차 실행하고, 실패하면 바로 멈추며, 성공한 캐시를 재사용합니다.

1. 학생생활관 점심: 닭갈비·단호박·쌈채소·마늘쫑·김치·오렌지·밥·국이 구분되는지 확인.
2. 학생생활관 저녁: 고등어·미트볼·나물·김치, 밥 하나와 국그릇 위치 확인.
3. 승선생활관 아침: `밥/잡곡밥`이 흰밥 하나인지, 반찬이 빠지지 않았는지 확인.
4. 교직원 점심: `백미밥/흑미밥` 통합, 냉우동샐러드가 국으로 오분류되지 않는지 확인.
5. 돈가스: 큰 왼쪽 원형 칸과 오른쪽 국그릇 확인.
6. 파스타: 밥·국·국그릇이 추가되지 않는지 확인.

결과는 `output/food-quality-live/report.json`, 각 샘플 폴더의 JPG, 학생생활관 전체 스토리 JPG에 남습니다. 보고서에는 전송한 이미지 프롬프트도 저장합니다. 모든 결과를 직접 열어 메뉴 누락·추가, 음식 위치, 식판 비율, 배경 경계와 가독성을 확인한 뒤에만 전체 완료로 판단합니다. 한도가 다시 소진되면 반복 호출하지 않습니다.

## AI 장애 시 게시 유지

AI 준비 단계의 예외 또는 AI 사진이 포함된 렌더링 실패는 원래 식단으로 복구하고 AI 사진 없이 렌더링하여 게시한다. 사진 없는 렌더링과 게시 자체의 오류는 실패로 유지하며 게시 재시도는 하지 않는다. 무료 한도 초기화 대기 중에도 일반 식단 스토리 게시를 막지 않는다.
